# Phase22 SQL editor layout — test design

Mode: test design. User-approved three-UI follow-up; Phase22 stays in progress. Root owns editor behavior/tests/native evidence; UI owner owns source panes/splitter/CSS/helper tests; Quality owns new `e2e/phase22-editor-layout.spec.ts`, affected old Enter expectations only, and independent review. No backend/DTO change.

| ID | Acceptance condition / scenario | Layer and owner | PASS evidence |
| --- | --- | --- | --- |
| T-P22-LAYOUT-001 | Source pane split pointer adjustment | UI helper/component; Quality E2E | Accessible horizontal separator between Tables and selected columns. Drag moves boundary, both panes remain independently scrollable; selection, alias/mode, authored SQL and column virtualization preserved. Split affects vertical space only. |
| T-P22-LAYOUT-002 | Keyboard and cancellation | UI component; Quality browser | Focusable separator with orientation/value/min/max; ArrowUp/Down changes height, Home/End clamps. | T-P22-LAYOUT-007 | Final integration/native | Quality review + Root fixed gates | Focused E2E and owner unit/static checks, single final full browser regression, three actual screenshots/geometry and independent image opening. Actual WebView split/long-line tail/Enter smoke and final product version/hash/size. Browser evidence does not certify native clipboard/OS IME. |

Risk focus: splitter drag must not steal existing row selection or virtual-list scrolling; constraints must be computed after resize, not cached forever. Escape/pointercancel must restore the pre-drag ratio/height. Editor overflow may originate in a parent flex/grid min-width constraint; merely adding a cosmetic scrollbar is insufficient. Newline behavior must not bypass completion acceptance or IME guards. No test timeout/count/security criteria are relaxed, and no Phase-wide promotion is inferred.
