# Phase22 identifier insertion — test design

Execution mode: test design. Scope: user-approved SQL insertion formatting only; authored SQL is never rewritten. Root owns product helpers/provider/examples/native checks; Quality owns Phase22 E2E expectations and independent review. Phase22 remains in progress.

| ID | Contract and scenarios | Layer / owner | Expected result |
| --- | --- | --- | --- |
| T-P22-ID-001 | ASCII identifiers, case, boundaries | Root pure tests; Quality browser | `[A-Za-z_][A-Za-z0-9_]*` names are bare only when absent from bundled parser keyword list. Include `orders`, `_a`, `a0`, `A_B`, ordinal `c1`, qualified aliases and tables. Existing always-quote helper remains unchanged. |
| T-P22-ID-002 | Keywords and unsafe names | Root data parity/unit; Quality browser | `select`, `order`, `from`, `qualify`, `asof` and mixed-case forms remain quoted according to authoritative parser keyword membership. Empty, space, punctuation, leading digits, non-ASCII, double quotes and SQL injection-shaped identifiers are quoted/escaped. No source text is executed by choosing a completion. |
| T-P22-ID-003 | Insertion paths and JOIN | Root model/editor tests + native; Quality E2E | Table/column completion, bulk insert, examples, guidance and inferred JOIN use the new helper consistently. Four name/c-number JOIN combinations keep physical mapping and actual COUNT3 golden. Korean original names remain quoted while safe table/local aliases/cN become bare. |
| T-P22-ID-004 | Existing SQL, quoted token, undo | Root editor/model + Quality E2E | Metadata change does not rewrite SQL. Explicitly quoted partial-token completion produces one valid identifier without doubled surrounding quotes or leftovers; embedded quotes escape correctly. Choosing an insertion preserves focus and can be undone; existing exact-result provenance remains sensitive to actual authored text. |
| T-P22-ID-005 | Keyword authority and bounds | Root generator/unit + independent source review | Generated JSON is synchronized with bundled DuckDB1.10504.0 kwlist.hpp. All three bundled build source copies have the same SHA. Every parser keyword is conservatively quoted, case-insensitively; no invented generic SQL subset substitutes for that list. Candidate/document bounds and metadata-only typing remain unchanged. |
| T-P22-ID-006 | UI/regression/native/product evidence | Quality three-viewport E2E/images + Root native/build |1440×900,1024×768,800×600 actual completion/example display and inserted SQL are readable; popup stays bounded. Existing tests retain safety/keyboard/counter assertions and adjust only generated-SQL expectation strings to this approved contract. Actual WebView four-mode query golden, hashes/settings restoration and final EXE version/size are recorded distinctly from browser mocks. |

Implementation tests cover full ASCII/unsafe boundary combinations, keyword list parity, quoted replacement and editor undo. Quality tests exercise representative real DOM insertion paths and preserve prior source-lifecycle, quiet-mode, disclosure and exact-result provenance checks. No new fixture format, backend DTO or capability is needed. Browser mocks prove insertion behavior, never SQL execution correctness; Root's actual Tauri acceptance proves resulting SQL. Final focused checks precede the single full regression/build after source freeze. Any failing mandatory gate remains BLOCKED until evidence; no Phase completion or promotion is inferred.
