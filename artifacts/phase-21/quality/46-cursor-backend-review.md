## Middle-selection replacement source review

The former whole-range rank sort failed the constrained large gate (Root preserves `16-04-24` evidence). Its source review above is historical and does not imply runtime acceptance. The newly frozen fallback replaces that sort with exact rank selection: sample at most257 fixed-width rowids by seeded hash, sort only their typed keys to select a median pivot, count rows strictly before it inside exact lower/upper bounds, then narrow the rank interval. At <=4096 remaining rows, bounded TopN resolves the predecessor anchor and ordinary seek reads the requested page. At most64 iterations are allowed; exhaustion fails explicitly.

**Replacement scoped source verdict PASS; no new confirmed HIGH/MEDIUM defect.** Rank arithmetic is consistent with selecting offset−1: equality returns the predecessor pivot; lower-half exclusion retains target; upper-half exclusion subtracts count+1. Bounds use the same full exact/null-safe comparator as seek, including unique rowid, so sampling affects performance rather than correctness. Only validated database rowids become numeric SQL literals; values/search remain handled by existing typed SQL/parameters. Variable-sized Rust collections are bounded257/4096, not target offset. The existing tail path remains bounded4096+take.

Production page and copy paths resolve with task/budget callbacks before the common reader; they remain inside the connection interrupt/monitor scope. Guards run between sample, typed-pivot and exact-count stages and iteration boundaries. The reader's secondary no-op resolution sees an already resolved anchor (or first/tail no-op), so it does not bypass production guards for middle selection. Copy reuses the resolved anchor while shrinking byte batches.
