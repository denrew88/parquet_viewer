# Column-values cursor focused test plan

Execution mode: test design, Phase 21 follow-up explicitly requested by user. Own scope is this proposal only; Root freezes DTO/contracts and integrates common documents. Existing fixes/evidence remain intact. No main-grid change, unrelated feature or formal promotion.

## Contract decisions before implementation

- Page request retains offset/limit/search/order and optional opaque cursor; response **requires nullable** nextCursor/previousCursor fields. Missing response fields are invalid. A token is bound to document/session/operation snapshot generation, search, order, offset, page size, direction and internal unique row identity. Frontend receives no typed anchor values. Repeating a valid request/token is idempotent while its snapshot and bounded registry entry remain live.
- Root froze compatibility in `00-scope.md`: legacy cursorless nonzero offsets remain supported through reverse-tail lookup or bounded spillable ranking, **without SQL OFFSET**. Independently test first/middle/tail and quota/cancellation for that fallback; ordinary UI Previous/Next must still use issued cursors. This replaces the initial cursor-only rejection recommendation. A fallback cannot conceal the existing OOM by raising memory/storage limits.
- Every order uses the entire deterministic comparison key, including value/count, category flags, exact typed key, invalid raw tie and final unique snapshot row identity. Previous-page traversal reverses the predicate and scan direction, then restores requested display order. Search is applied before seek and exact matchedCount remains independent of the loaded page.
- Token registry has explicit per-snapshot/global count and byte bounds. Unknown, evicted, malformed, cross-snapshot or mismatched tokens fail with a typed restart-from-first message; they cannot read another document or silently select a different anchor. Reset search/order/scope/page size invalidates frontend navigation state. Cancellation/close releases tokens with snapshot resources.

## Execution and completion

Implementation owner supplies seek/token/copy unit tests and meaningful regression coverage. Quality supplies independent expected ordering, browser interaction/geometry and frozen-source/runtime review. Root runs native/release verification and common gates. Extend existing fixtures rather than regenerate/move large inputs. Existing original grouping bug and known last-OFFSET OOM evidence remain historical failures until corrected actual-native evidence is recorded.

Acceptance is blocked by any incorrect exact count/order, missing/duplicate value, token cross-snapshot access, unbounded resource path, partial clipboard publication, actual1GiB late-page failure, or unexecuted required native gate. Do not weaken quotas, precision or existing copy limits. No additional unrelated migration/installer/DPI/cleanup testing is introduced by this plan.
