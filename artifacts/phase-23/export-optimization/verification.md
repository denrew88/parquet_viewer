# Phase 23 SQL 내보내기 타입 변환 경량화

DuckDB 1.5.4에서 SQL Arrow → 임시 Parquet → DuckDB Arrow 왕복으로 초 타임스탬프는 Int64, 밀리초 타임스탬프는 마이크로초 타임스탬프로 읽히는 것을 확인했다. 같은 타입의 배열은 그대로 넘기고, 초는 값 버퍼를 재사용해 타입을 복원한다. 밀리초는 값이 1,000으로 나누어떨어지는 경우에만 복원한다. 다른 타입 조합은 오류를 반환한다.

같은 검증용 앱 식별자와 프런트엔드에서 EXE는 67,526,144바이트에서 60,955,136바이트로 6,571,008바이트 줄었다. 검증용 EXE의 SHA-256은 `38d85db68e64e3bed2b070bae0fb565fae70eba2aa67fe33e191710ec037d6c2`다. [정식 제품 EXE 기록](../product-exe.json)

같은 JOIN 스냅샷의 240,000행에서 필터로 선택한 180,000행을 내보냈다. 짧은 텍스트와 긴 텍스트, 원래 순서와 섞인 순서, CSV와 Parquet의 조합 8개에 타임스탬프 컬럼을 추가한 2개를 더해 비교했다. 예열 후 기존 코드와 새 코드의 실행 순서를 번갈아 3회 반복했다. 모든 회차에서 CSV 바이트 또는 Parquet의 타입·값·행 순서가 일치했다.

| 긴 텍스트와 섞인 순서 | 형식 | 기존 중앙값 | 변경 중앙값 |
| --- | --- | ---: | ---: |
| 기존 컬럼 | Parquet | 879.69 ms | 865.08 ms |
| 기존 컬럼 | CSV | 1,032.29 ms | 1,042.79 ms |
| 초·밀리초 타임스탬프 추가 | Parquet | 876.35 ms | 882.32 ms |
| 초·밀리초 타임스탬프 추가 | CSV | 1,259.01 ms | 1,251.98 ms |

[JOIN 측정 원본](comparison.json) · [타임스탬프 포함 측정 원본](timestamp-adapters.json)

Rust 포맷과 Clippy가 통과했다. 전체 실행에서 406건이 통과했다. 추가 검증 두 건은 fixture 문법과 오류 발생 시점의 기대값을 수정한 뒤 집중 재실행에서 통과했다. Windows 앱 검증 6건이 통과했고 같은 fixture를 내보낸 파일의 SHA-256도 기존 빌드와 일치했다. 정확성 검사에는 UInt64, 38자리 소수, 초·밀리초·나노초와 UTC 타임스탬프, 유니코드, 바이너리, NULL, 빈 Parquet가 포함됐다. [Windows 실행 기록](native-report.json)

밀리초 타임스탬프의 ±infinity는 DuckDB가 보기를 읽는 중 거부한다. 원본 결과는 그대로 내보낼 수 있다. 해당 보기 요청이 실패하면 새 파일을 만들거나 기존 파일을 덮어쓰지 않는다.
